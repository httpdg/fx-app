# FX Signal App — фундамент

Скелет: вход через Telegram (без пароля), сессия, RLS-изоляция в Postgres,
дизайн-система, оболочка с нижней навигацией. Бизнес-логики (сигналов) ещё нет.

## Что нужно поставить один раз

1. **Node.js** (LTS) — https://nodejs.org, просто скачать и установить, ничего настраивать не нужно.
2. **Git** — https://git-scm.com/download/win, тоже просто установщик с настройками по умолчанию.
3. Аккаунт на **github.com**, если ещё нет.

Проверь после установки — открой PowerShell (Пуск → набрать powershell) и введи:

```
node -v
git --version
```

Обе команды должны показать версию, а не ошибку.

## Шаг 1. Залить код на GitHub

Разархивируй эту папку куда угодно, например в `C:\projects\fx-app`.
Открой PowerShell и введи по очереди (замени пути и ссылку на свои):

```
cd C:\projects\fx-app
git init
git add .
git commit -m "foundation: auth, RLS, design system"
```

Дальше зайди на github.com → New repository → назови как хочешь (например `fx-app`) →
**не** ставь галочку "add README" → Create repository.
GitHub покажет две строчки вида `git remote add origin ...` и `git push ...` —
скопируй и выполни именно их в том же PowerShell.

## Шаг 2. Postgres — миграция и роль

В Railway у тебя уже есть Postgres. Открой его вкладку **Data** →
там есть Query — вставь туда содержимое файла `sql/001_init.sql`, но
сначала замени `ЗАМЕНИ_НА_СВОЙ_ПАРОЛЬ` на любой свой пароль (два места в файле,
там где создаётся роль `app_user`), и выполни.

Дальше собери строку `APP_DATABASE_URL`. Открой вкладку **Variables** у самого
Postgres в Railway, найди `DATABASE_URL` — она вида:

```
postgresql://postgres:пароль@хост.railway.internal:5432/railway
```

Замени в ней `postgres:пароль` на `app_user:твой_пароль_из_шага_выше`, хост и
базу оставь как есть. Это и будет `APP_DATABASE_URL`.

## Шаг 3. Деплой бэкенда на Railway

В своём Railway-проекте: **+ New → Deploy from GitHub repo** → выбери репозиторий,
который только что запушил.

В настройках сервиса, вкладка **Variables**, добавь:

- `BOT_TOKEN` — токен из BotFather
- `SESSION_SECRET` — любая длинная случайная строка (можно сгенерировать в PowerShell:
  `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`)
- `APP_DATABASE_URL` — то, что собрал в шаге 2
- `DATABASE_URL` — обычная строка от Railway, оставь как есть (нужна только для
  тестового скрипта изоляции, сервер её не использует)
- `NODE_ENV` — `production`

Railway сам определит, что это Node-проект, выполнит `npm run build` и запустит
`npm start`. Если что-то не соберётся — вкладка **Deployments → View Logs** покажет,
на чём упало.

После первого успешного деплоя: **Settings → Networking → Generate Domain** —
получишь адрес вида `что-то.up.railway.app`.

## Шаг 4. Привязать адрес к боту

В BotFather: `/mybots` → выбери бота → **Bot Settings → Menu Button** (или
`Configure Web App`, в зависимости от версии BotFather) → вставь туда
`https://что-то.up.railway.app`.

Открой бота в Telegram — должен открыться экран с пустыми вкладками снизу,
без какого-либо экрана входа.

## Проверка изоляции (сделать до любой новой фичи)

На своём компьютере, в папке проекта (один раз):

```
npm install
```

Дальше:

```
$env:DATABASE_URL="строка из шага 2, обычная (postgres:пароль@...)"
$env:APP_DATABASE_URL="строка из шага 2, с app_user"
node scripts/test-isolation.mjs
```

Должно вывести три `OK:`. Если хоть один `ПРОВАЛ:` — не переходи к следующей
фиче, пока не разберёшься, откуда течёт.

## Локальная разработка (по желанию)

```
npm run install:all
```

Терминал 1:
```
cd server
copy ..\.env.example .env
# впиши значения в .env
npm run dev
```

Терминал 2:
```
cd web
npm run dev
```

Фронт откроется на `http://localhost:5173`, но проверить вход через Telegram
локально не получится — Telegram отдаёт initData только внутри самого
мессенджера. Локальная разработка годится только чтобы смотреть на вёрстку
экранов и навигацию.

## Что срезано в этой итерации

- Нет rate-limit на `/api/auth/telegram` — не критично, эндпоинт и так
  проверяет подпись, но при желании стоит добавить позже.
- Сессия — самодельная подписанная кука, а не что-то вроде Redis-сессий.
  Для одного бота это нормально, если юзеров станет много тысяч — можно
  будет заменить, код авторизации изолирован в `auth.ts`.
- Сборку и `npm install` в своём окружении не проверял — нет доступа в
  интернет там, где я работаю. Код написан аккуратно и по документации
  библиотек, но первый реальный прогон `npm install` и `npm run build`
  сделаешь ты, и если что-то не так — я поправлю.
